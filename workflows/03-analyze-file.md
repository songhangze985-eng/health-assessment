# 分析文件

有文档或表格时先走这里，再打分。原文复制到 `inbox/`。

1. 能抽出日期的，按日期写成多条会话。
2. 整份都没有日期：问用户是不是全部算某一天，以及是哪一天。
3. 用户说不清是哪一天：默认今天，`date_defaulted` 设为 true。这一天只计 1 天，不能把一篇文档拆成 7 天。
4. 抽出的蛋白质、组数、重量、评价分类写入对应字段。抽不出的字段留空，不要补假数。
5. 文中出现红旗词时改走 [06-red-flag.md](06-red-flag.md)，不继续打分。

分析报告写入 `analyses/`，内容使用计分脚本的 JSON，不另写一套分数。

## 本地接口

本机服务在听 `127.0.0.1:8765` 时，表格和图片交给 `POST /api/checkin/file`。请求 JSON 含 `filename` 和 `file_base64`，可选 `date` 与图片说明 `caption`。

- `.csv` 与 `.xlsx` 在本地解析，不调用大模型。对得上的列写入蛋白质、抗阻分钟、超负荷、1–5 自评、评价分类、睡眠、步数、静息心率、抗炎饮食、压力缓解和专注力。对不上的列留空，不补假数。
- 图片只在配置了 `LLM_API_KEY` 时提取。没有 Key 时只保存说明文字。
- 同一天已有穿戴记录时，训练时长和蛋白质保留穿戴数据；超负荷和心理自评保留本人自述。
- 结果写入该库 `sessions/YYYY-MM-DD.json`。一篇没有日期的文件仍然只算 1 天。原文里的红旗词改走 [06-red-flag.md](06-red-flag.md)，这轮不继续当正常分数。
